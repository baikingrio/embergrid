# 跨用户画布同步延迟修复

## 原因与改动

- 原实现每 15 秒轮询 `Painted`，双浏览器回放确认事件时，A 的像素延迟 14,913 ms 才变色。全量快照另有约 60 秒轮询和 8 秒缓存。
- 改为每秒读取 `/api/canvas-updates`，服务端在单实例内合并并发请求并缓存 750 ms；通过无状态日志查询避免依赖 RPC filter 的生命周期。页面隐藏暂停请求，失败退避，接口不可用时回退直连 RPC。
- 公共 RPC 拒绝 128 区块范围，实测 32 区块查询可用，增量窗口因此设为最近 32 区块。窗口不足时先读取最新全量快照，不能直接跳过缺失事件。
- 按区块和 logIndex 排序、按交易哈希与 logIndex 去重；同一批事件只复制数组和触发绘制一次，支持同一交易多格及同一区块多次改色。
- 原先颜色覆盖保护一直等待快照颜色相同，可能遮住其他用户后续改色。现在按区块版本释放保护；全量快照的全部分页固定到同一区块，旧快照无法覆盖较新的事件。

## 验证结果

| 检查 | 结果 |
| --- | --- |
| 同一双浏览器事件回放，保持全量快照落后 | 优化前 14,913 ms，最终回归 687 ms；两端无页面异常 |
| 两个真实浏览器、本地 Anvil 链实际购买 | B 的交易成功，A 在 450 ms 后显示新颜色 |
| 购买后切换页面可见性，再读缓存旧快照 | 新颜色未回滚 |
| 公共 RPC 增量接口只读验证 | HTTP 200，单次约 911 ms，覆盖 32 区块 |
| 单元测试 | 20/20，通过改色保护、同块覆盖、去重、断档和落后节点回归 |
| vue-tsc / Nuxt 生产构建 / git diff --check | 通过 |

450 ms 是隔离本地链结果，687 ms 是受控事件回放结果，均不能作为公网延迟承诺。公网仍受 RPC、网络与服务端冷启动影响。

实际购买测试使用隔离 Anvil 链、临时浏览器钱包与本地铸造余额，浏览器禁止所有外部 HTTPS。没有发送公共测试网交易或使用用户钱包资金。本次修复尚未部署到 Vercel。
